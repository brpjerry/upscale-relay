This release fixes the findings of the October code audit across the server,
the desktop client and the shared media layer, and moves the server's NVIDIA
runtime forward. Upscale Relay Android v0.24.0 is its counterpart.

Playback through the server:

- Colours match the original. Output is tagged with the source's colour
  space, and untagged files are read the way mpv reads them, which fixes
  shifted hues on upscaled SD video and wrong contrast on full-range sources.
- Anamorphic video (DVD-style non-square pixels) is shown in its correct
  shape: a 720x576 16:15 source comes out as 1440x1080 at 1080p instead of
  1350x1080.
- Variable-frame-rate video keeps its exact frame timing instead of being
  snapped to the average frame rate, and FFV1 source files now play.
- 4K sources work with TensorRT models instead of failing as playback
  starts. They are not realtime with every model: about 8 fps with AnimeJaNai
  Compact on an RTX 5090.
- Library playback keeps its audio and subtitles after rapid seeking, and
  audio that continues past the last video frame arrives without waiting for
  the end of the file.

Desktop client:

- A local or network file that can no longer be read ends playback with
  "Could not read the source file" instead of buffering forever, and rapid
  seeks in a local file can no longer end the new position's stream early.
- A pause made with an input.conf key binding stays paused across seeks,
  playback-setting changes and the fallback to local playback, and the
  toolbar shows it.
- After the laptop sleeps or the network drops during playback, the client
  reconnects by itself and waits for the server to release the old session
  before opening another, instead of stopping at "Server cleanup not
  confirmed". Playback that has lost its server ends within seconds rather
  than buffering forever; opening the file again resumes where it stopped.
- Watch history and the Server tab's state follow the server rather than
  its address, so they survive an IP change. Server-file history starts
  fresh once with this version; local-file history is kept.
- Two players starting at once no longer take each other's subtitle fonts,
  and interrupted font downloads no longer grow the cache past its limit.
- Starting a video while the server library is still loading no longer
  leaves the Server tab stuck on "Loading", and on Windows autoplay
  continues past the first next file.

Server:

- The NVIDIA runtime moves to ONNX Runtime 1.31 and CUDA 13.4; TensorRT stays
  on 10.16, the newest version ONNX Runtime can load. The first launch of
  v0.24.0 downloads the new runtime once (about 4 GB) into a new folder
  under `%LOCALAPPDATA%\upscale-relay\runtimes`. The previous folder
  (`ort1.28.0-…`, about 4 GB) is not removed automatically and can be
  deleted by hand. Existing TensorRT engine caches stay valid.
- A stalled session can no longer exhaust server memory: input buffering is
  bounded at 128 MiB per session. If the GPU inference worker crashes and
  could only come back on the CPU, the session ends with a clear error
  instead of crawling.
- Servers announce a stable identity (`server_id`), and `GET /status` is now
  a documented contract that clients use to confirm a session was released.

The Arch Linux client package and Windows server ZIPs use version 0.24.0.
No protocol version change is required: the new `sample_aspect_ratio` and
`server_id` fields are optional, and older clients and servers interoperate.
